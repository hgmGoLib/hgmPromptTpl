# hgmPromptTpl

给 AI 提示词用的极小模版引擎。**只解决一件事：几份提示词之间的信息复用。**

不是通用模版引擎，不做条件、循环、函数、对象，以后也不打算做。

## 为什么有它

它是从一个真实项目里长出来的：那个项目有三份给 AI 的提示词，里面有大量同样的规矩（落盘纪律、
写操作授权边界、环境自救、说明书口径……）。以前靠人手抄三份，结果是 26 处「近似但不一致」——
同一条规矩在三份里说法不同，改了一份忘了另两份，AI 收到的规矩就是漂的。

把共同的段落抽成一个文件、三份都 include 它，问题就没了。需要的语法就四条，别的都是负担。

## 装

```
go get github.com/hgmGoLib/hgmPromptTpl
```

需要 Go 1.24+，无第三方依赖。

## 上手

模版包就是一个目录，里面三种文件：`xxx.ep.txt` 是入口文件（只能被渲染），`xxx.part.txt`
是复用文件（只能被 include），`xxx.raw.txt` 是原样包含文件（一个字节都不解析）。
别的后缀扫描时直接忽略。

```go
// 建包这一步就把编译检查跑完了：建得出来的包就是检查通过的包，没有一个单独要记得调的检查方法。
// 一次把所有静态问题全报出来，每条都带「原始文件名:行号」
tpl, err := hgmPromptTpl.NewFromDir("./example/prompt")

ep, err := tpl.GetEp("找bug.ep.txt")

// 渲染这份提示词要准备哪些变量，模版自己说了算，渲染之前就能问出来
ep.GetVarNameList() // [adminPassword consolePort fileNameBlock linuxIp]

// varMap 的 key 集合必须跟上面那份名单完全一致：少一个报错，多一个也报错。值可以是空串
text, err := ep.Render(map[string]string{
    "linuxIp":       "10.10.10.10",
    "consolePort":   "8080",
    "adminPassword": "pw123",
    "fileNameBlock": "* pkg/httpApi/user.go",
})
```

这三个都有 `Must` 版（`MustNewFromDir` / `MustGetEp` / `MustRender`），出错直接 panic，
panic 出来的就是那个 error 本身，报错内容一个字不变。参数是代码里写死的就用 Must 版少一层缩进，
参数来自运行时（命令行、配置、用户给的目录）就用原版自己处理 err。

变量名单只有一份，就是模版本身 —— 调用方不用再声明一遍拿去比对，也就不存在两份名单对不齐。
「多给了也报错」是有意的，它白送一条 fail-closed：哪天有人把模版里的 `{{linuxIp}}` 删了改成
写死的 IP，渲染出来的提示词依然通顺，光看结果字符串判断不出来 —— 但你手写的 varMap 里还留着
`linuxIp` 这个 key，Render 当场报「多了」。代价是一份 varMap 喂不了所有入口文件，得按入口文件
各建各的。

能跑的完整例子（启动自检怎么写、fail-closed 怎么用、不可信的变量值怎么处理、各种报错长什么样）：

```
go run ./example
```

## 语法一共四条

| | 写法 | 说明 |
|---|---|---|
| 变量 | `{{linuxIp}}` | 只支持字符串。前后不许有空格。值原样输出，不会再被当模版扫一遍 |
| 包含 | `{{@include sub/x.part.txt}}` | 路径永远是模版包根目录向下的相对路径，分隔符固定 `/`。不支持传参 |
| here doc | `{{\|VUE\|里面的 {{x}} 原样输出\|VUE\|}}` | 里面一律当字面量，内容可以跨多行。`VUE` 可以换成任意「字母开头的字母数字」 |
| 原样包含 | `{{@includeRaw sub/x.raw.txt}}` | 那个文件的全部字节当字面量，**一个字节都不解析** |

**正文里只要出现连着两个左花括号或者连着两个右花括号，就得包起来。**
会撞上的场景：Vue / Handlebars / Jinja2 的 `{{ }}`、Go 的 `text/template`、GitHub Actions 的
`${{ secrets.X }}`、C 的嵌套初始化列表 `{{1,2},{3,4}}`、LaTeX 的 `{{\bf x}}`。

包起来有两条路，费脑子的方向不同，自己挑：

| | 要记的规矩 | 跳转 | 适合 |
|---|---|---|---|
| here doc | 一条：同一个文件里 `{{\|NAME\|` 和 `\|NAME\|}}` **各只准出现一次**（引擎会查，多了少了都报错） | 无 | 想跟正文放在一起看的片段（内容可以跨多行，几个字到几十行都行） |
| `.raw.txt` | **零**。那个文件没有任何定界符落在内容里，所以「里面能放什么」这个问题不存在 | 每处一跳 | 整段外来内容（一份 Go 模版、一段 CI 配置） |

here doc 那条唯一性不是风格检查，它让「引擎在你没想到的地方提前闭合、渲染出一份错的提示词却
不报错」在结构上不可能发生。撞上了就换个名字（名字按内容取：`VUE` / `GOTPL` / `YAML`），
或者整段挪进 `.raw.txt`。为什么是这么选的见 [doc/设计决策.md](doc/设计决策.md) 第一节。

## 建包会替你挡住什么

* 语法错（含 here doc 的开头/收尾唯一性）
* 模版包里一个入口文件都没有
* include / includeRaw 的目标文件不存在
* 复用文件、原样包含文件从入口文件出发走不到（死文件）
* 复用文件只被 1 个文件引用、内容又不到 600 字节（单调用者该内联回去；`.raw.txt` 不受这条管）
* 同一个被包含文件在一棵展开树里出现两次（互相 include 成环也撞这条）

报错不是遇到第一个就返回，是一次全报出来，每条都带「原始文件名:行号」——渲染结果是个谁都
没见过的拼接产物，报「渲染后第 240 行」等于没报。

这些检查绕不过去：没有「只解析不检查」这个中间状态，Tpl 建得出来就是全过了。剩下唯一一件
引擎判不了的事是「模版用到的变量，本程序填不填得上」——那是调用方那头的事，
拿 `GetEpList()` + `GetVarNameList()` 在启动时自己扫一遍，写法见 example/main.go 的 loadTpl。

## 它明确不管什么

* **提示词注入防护**。变量值一个字节都不加工，原样进最终提示词。值的来源不可信时，
  挡换行和控制字符、给多行数据包随机定界符，都是调用方自己的事——写法见
  [example/main.go](example/main.go)，完整口径见 readme.txt 七之二。
* 条件、循环、对象、函数、变量定义、include 传参。
* CRLF / BOM / 首尾空白的归一。字节进，字节出，换行符交给 git 管。
